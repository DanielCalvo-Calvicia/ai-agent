## Goal

Know that every Gemini id the work keeps is accepted by the key of this project, and that the free-tier limits are not a surprise. The review of 2026-10-27 could not do it: `.env` is not in every checkout. **The maintainer runs it**; the assistant prepares the command and runs nothing itself.

## Specification

1. Where `.env` exists, run one tiny call per Gemini id of the catalog, through the OpenAI-compatible endpoint (`GOOGLE_URL`), as the first `api_check` of 2026-09-21 did, with `tests/manual/check_google_ids.py` (see Notes). It costs almost nothing.
2. Ids to check: `gemini-3.1-flash-lite`, `gemini-3.5-flash-lite`, `gemini-3.8-flash`, `gemini-3.6-flash`, `gemini-3-flash-preview`, `gemini-3.1-pro-preview`, `gemini-4-argon`, and, as a last look, `gemini-2.5-flash`, `gemini-2.5-flash-lite`.
3. A Google id that fails is removed in T-02.4 and T-02.6, with the error in *Notes*.
4. Send about ten short requests in a row to `gemini-3.8-flash` and `gemini-3.1-flash-lite` and write down whether the free tier refuses any (the limits are not on Google's pricing page).
5. Record each result and the date in `api_check`, and the rate-limit result in *Notes*.

## Acceptance criteria

Every id kept has an `api_check` of the date of the run; the result of the rate-limit probe is written down.

- **2026-10-28, ready to run (prepared by the assistant, not run).** No script for this check existed (the first `api_check` of 2026-09-21 was done by hand), so `tests/manual/check_google_ids.py` was written: one tiny real call per `GoogleModels` id through the route the agent uses (`resolve_provider_model`, `GOOGLE_URL`, `GOOGLE_API_KEY`), with the prompt "Reply with the single word OK." and at most 200 tokens. Each call is a few tokens (free on the free tier). No user data is sent. The script prints and writes (to `tests/output/check_google_ids.md`) the id, the result, the seconds, the tokens (sent, answered, thinking) and the start of the answer or the error with the key masked; it edits no file. Tested here without any key: `--dry-run` lists the ids and makes no call, and a real run without the two variables stops with exit code 2 before any call.
  1. In `.env` (or the shell), never in git: `GOOGLE_API_KEY` and `GOOGLE_URL`. Decide which key: a free key (the default of ADR-012; Google uses free-tier content to improve its products, but this script sends one word) or a billed one (then `gemini-4-argon` and `gemini-3.1-pro-preview`, which have no free tier, can be checked; a free key may refuse them, and that refusal is a result, not an error of the script).
  2. From the `ai-agent` folder:
     ```powershell
     $env:PYTHONPATH = "D:\Snowfactory\Programas\Python\shared-logging"   # only while shared-logging is not installed in the venv
     windows\Scripts\python.exe tests\manual\check_google_ids.py --dry-run     # the ids and which variables are set; no call
     windows\Scripts\python.exe tests\manual\check_google_ids.py               # one call per id (9 calls)
     windows\Scripts\python.exe tests\manual\check_google_ids.py --probe=10    # the same, plus 10 calls in a row to each default model (20 more)
     ```
     Add `--pause=2` to space the probe calls, and `--ids=gemini-3.8-flash,gemini-4-argon` to check only some ids. The ids checked by default are the nine of `GoogleModels`: `gemini-4-argon`, `gemini-3.8-flash`, `gemini-3.6-flash`, `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, `gemini-3.1-pro-preview`, `gemini-3-flash-preview`, `gemini-2.5-flash`, `gemini-2.5-flash-lite`.
  3. Read the table. Per id: `answered` (the id works with this key) or `FAILED` with the error (a 404 "no longer available" is what `gemini-2.5-pro` returned; a 403 or 429 on a paid-only id with a free key is a tier refusal; a 400 on a parameter is a problem of the route, not of the id).
  4. Record, in `config/gemini_models.json`: `api_check` of each model of the file = `"answered"` or `"FAILED: <code>, '<message>'"` (the tests require exactly one of the two forms, and a model that is FAILED must be rated `avoid` on every step, or be removed), and write the date of the run in the `_api_check` text. The probe result goes in these Notes: how many of the 10 calls each default model answered and the first error (a 429 means the free-tier limit is reached by a burst; the pipeline makes about 7 calls per message).
  5. Follow-ups that this run unlocks (the assistant does them after the result): for an id that failed, remove it from the catalog and the price files (T-02.4 and T-02.6 say how); for `gemini-4-argon` and `gemini-3-flash-preview` that answered, add them to `config/gemini_models.json` (prices in PR-004 section 3.4; `free_tier` false for `gemini-4-argon`; ratings as an estimate; `THINKING_FACTOR` entries in `tests/cost_estimate.py`) and regenerate `docs/models/*`; then close this task.
