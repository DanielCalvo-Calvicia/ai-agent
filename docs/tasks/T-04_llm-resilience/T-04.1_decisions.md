## Goal

Fix what the fallback does before it is built. The maintainer asked for it ("do 1, 2, 3") and left the design to the assistant; each point below is the assistant's proposal, taken as the default.

## Resolution

1. **What is a lack of capacity:** HTTP 429, any 5xx, a timeout, no connection. A 400, 401, 403 or 404 never falls back (they were never retried either). A bad answer (invalid JSON) is not a capacity problem.
2. **The wait:** `AI_AGENT_RETRY_WAIT_SECONDS` (default 1; 0 = none), doubling on every try, never more than 8 times the value, only after a lack of capacity. A 429 that says "per day" skips the rest of the tries on that model (waiting seconds cannot help).
3. **Which models:** `fallback_models` (a list of ids) in a **profile**, tried once each, in order; `AI_AGENT_FALLBACK_MODELS` (comma list, empty = none) wins. Not a global list, so a profile decides what may receive its data.
4. **Who has one:** `proven` and `google_free` get `gemini-3.5-flash-lite` then `gemini-3-flash-preview` (both answered on 2026-10-28, both free tier). The Claude profiles and the others get none.
5. **The failure** when nothing answers is the one of the chosen model, with its category, so the apology does not change.
6. **The record:** the metrics and the cost tables name the model that answered.
