## Goal

Write the steps that T-06.1 asks for, each as a JSON declaration, a prompt and, only if needed, a named Python function (PR-005 section 3.2).

## Files

| Action | Path |
|---|---|
| Create | `step_defs/<name>.json`, `prompts/<id>_<name>.txt` for each new step |
| Modify | `schema/response/general/full.schema.json` and the generated tree (`python scripts/split_schemas.py --write`) **only if** a new schema piece is needed; a developer adds it, a non-coder cannot (Q08-6) |
| Modify | `config/state_fields.json` if a step needs a new field (then also `domain/` and the golden) |
| Create | `tests/test_new_steps.py` |

## Specification

- A new step reads and writes existing fields where it can. A case that T-06.1 names first: a step that reads the user's message, chooses a tool inside the allowed list of its profile and calls it, and writes the result for the draft writer (the "tool caller" of Q07-4 A). It runs through `llm_per_action` or `llm` as the specification of T-06.1 says.
- The prompt is written against the schema, one step at a time, with the fixed set of T-06.2 run before and after.

## Acceptance criteria

Each new step assembles, answers on a scripted LLM, and passes its message of the fixed set on the real models (T-06.6).
