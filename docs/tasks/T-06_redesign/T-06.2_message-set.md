## Goal

A small, fixed set of messages with what a good answer must contain, so a prompt or a flow is judged by the same yardstick every time (Q08-5 A).

## Files

| Action | Path |
|---|---|
| Modify | `tests/manual/profile_messages.json` (T-05.17 made the first version) |
| Create | `tests/manual/README.md` (how to run it and read the results) |

## Specification

- Each message: the profile it is run on, the text, and a list of **expected points** (what the answer must say or do; for example "answers in Spanish", "states the number of orders", "asks which arm"). Real customer data never: sandbox codes only (`CL-1001`).
- At least: a greeting (Spanish and English), a question with no tool, a plan that needs a document, a movement, a Dynamics question, a message in Spanish for each profile that answers text, a message that must make the profile ask the user a question and the answer to it (the `pause_id` path).
- The set is read by `scripts/run_profile.py`; a run saves each answer and the points a human ticked in `tests/output/<date>_<profile>.md`. The judge is the maintainer (option A of Q08-5); an automatic judge is not part of this epic.

## Acceptance criteria

The set exists, each message has expected points, and a run on the mock adapter writes the file.

## Verification

The baseline of the [tasks README](../README.md) section 3.

## Notes

- 2026-11-04 (assistant). Files: `tests/manual/profile_messages.json` (13 messages), `scripts/run_profile.py`, `tests/manual/README.md` (new), `tests/test_profile_tools.py`. No real model or Dynamics call was made.
- **The set:** `greeting`, `greeting_es`, `question`, `spanish`, `impossible` (every profile), `document` and `plan` (identification, special, dynamics, default), `movement`, `movement_es` and `movement_ask` (movement; the first two also identification), `ask_family` (special, default), `dynamics` (identification, special, dynamics) and `dynamics_ask` (special, dynamics). Each has `points`; `points_for` replaces them where a profile answers something else (`identification` the classification, `gesture` the emotion, `movement` a non-movement message).
- **Differs from the task text:** (1) `expect` (one sentence) became `points` (a list), and the report prints each as `- [ ]` to tick by hand; the file is `tests/output/profile_run_<profile>_<date>[_<label>].md`, the name T-05.17 gave it, not `<date>_<profile>.md`. (2) New `--label` (`before`, `after`) so the two runs of a T-06 change do not overwrite each other. (3) The paused-run path is a `then` field: the script sends the user's answer as the next message of the same run (`MessageFlowService(paused=...)`, no HTTP `pause_id`, which is checked by the route, `tests/test_profile_api.py`). A profile that does not ask is reported as such and the answer is not sent. The set asks on purpose in `movement_ask` (which arm), `ask_family` (the names the robot cannot know, an example of the triage prompt) and `dynamics_ask` (which customer code).
- **Not done / not verified:** the points were written from the prompts and Q07 to Q09, not checked on a real model: the first real `before` run (with the maintainer's go) shows whether a point is too strict or whether a message does not make the profile ask. `document` expects an honest "I cannot create files" (the capabilities say so); if a model plans it instead, that is a finding, not a failed test.
- **Known hazard, not changed:** a `--mock` run still writes `tested: <date>` in the profile file (T-05.17 behaviour; the tests use a temporary root). Run it with `--root <copy>` or revert the profile afterwards; `tests/manual/README.md` says so. Marking only real runs would be a small change if the maintainer wants it.
