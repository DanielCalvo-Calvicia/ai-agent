## Resolution

2026-11-04, the maintainer in chat (written by the assistant):

- **Table:** accepted as drafted above: the seven profiles as T-05 built them, with the same flows, tools, models, inputs and returns.
- **Proposals:** none is decided now. The maintainer asked first to **read the original prompts and see whether each profile, flow and step can be improved**; later tasks verify the results. So the `dynamics` prompt append and the `robot_triage` prompt are created only if the review of T-06.4 or the real run of T-06.6 shows a prompt that must differ (Q09-8), and `robot_triage` is not created before that.
- **`special` and `dynamics`:** stay two profiles on the same flow; the MCP servers make them act as two different profiles. **`movement`** keeps today's flow (motion planner and validator): no writer and no editor.
- **Question 1, new steps:** none. The tool-calling step is the existing `mcp_operator` (the project manager picks the tool and its parameters; the operator runs it). T-06.3 has nothing to build and is closed with no change; no `tool_caller` profile.
- **Question 2, names:** yes: `movement` is the maintainer's `motion`, `gesture` is `emotion`.
- **Question 3, prompts to refine first:** none is wrong; the aim is to see whether each can be **better and use fewer tokens**. The review is in the Notes of [T-06.4](T-06.4_refine-prompts.md).
- **Question 4, what "better" means:** all of the options offered: shorter, in the user's language, fewer calls, fewer wrong greetings, cheaper.
