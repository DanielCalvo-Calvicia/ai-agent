## Goal

Improve the prompts that T-06.1 lists, without breaking the answer format, with a comparison for each (Q07-4: "the prompts also need refinements").

## Files

| Action | Path |
|---|---|
| Modify | `prompts/<id>_<name>.txt` of the steps in T-06.1 |
| Create | `prompts/profiles/<profile>/<step>.txt` where only one profile differs (a file named by `prompt_replace` or `prompt_append`) |
| Modify | `docs/rules/schemas-and-prompts.md` (what the prompt of each step says and why) |

## Specification

For **each** prompt, in this order:

1. Run the fixed set on the current prompt with the models of the profile; keep the output (`before`).
2. Change **one** thing (the instruction that T-06.1 names as wrong).
3. Run the same set again (`after`); keep it.
4. Write in *Notes* what changed, the messages whose answer changed and whether the expected points are met better, the same or worse. Worse: revert.
5. The golden file changes: read the diff first and regenerate on purpose (`UPDATE_GOLDEN=1`).

A prompt that differs for one profile is a profile override (T-05.14), not a change of the generic prompt.

## Acceptance criteria

Each refined prompt has a `before` and an `after` run and a note; none breaks its schema (`test_schema_tree.py`, `assemble()`); the maintainer read each changed prompt.

## Verification

The baseline of the [tasks README](../README.md) section 3. Real runs cost money: ask before each.

### Change 1: `9_answer_checker.txt`, `message_to_user` in the user's language (2026-11-04)

- **Change:** one phrase: "one short friendly message in English" became "in the language of user_reply" (item 5 of the review). Nothing else in the prompt or the schema; the golden file did not change (it does not pin this prompt), the generated `docs/models/profiles.md` changed only by the `tested` note of the real runs.
- **Runs** (real models, approved by the maintainer for `movement` only; `proven` set, `gemini-3.1-flash-lite`): `tests/output/profile_run_movement_2026-11-04_before.md` (8 messages, 11 calls, 15,747 tokens, $0.0054) and `..._after.md` (11 calls, 15,729 tokens, $0.0053). The first messages of `before` waited minutes on the free tier (up to 314 s); `after` did not: latency is not comparable.
- **Result: the same.** Every message answered in both; the two answers differ only in the wording a model varies by itself; the greetings, the refusal (`impossible`), both movements (1 and 2 movements) and the question path of `movement_ask` (asked, then one movement, 4 calls) behave alike. **The change was not exercised:** no message of the set made the checker answer `not_answered`, the only verdict that writes `message_to_user`, so this run can neither show it better nor worse. The points are not ticked: the report boxes are the maintainer's.
- **Kept**, because the old text contradicts the rule "in the user's language" and the risk is one phrase. To prove it, a message that answers a question badly in Spanish is needed (an idea for the set: `movement_ask` with a `then` that is not an answer, such as "¿y tú qué tal?", expecting a Spanish question again). Revert it if the maintainer prefers a change that a run can show.
- Not run: `default` and `special` (no approval), so the checker has not been seen on `claude_mixed`.
