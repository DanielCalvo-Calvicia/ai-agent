## Goal

Improve the prompts that T-06.1 lists, without breaking the answer format, with a comparison for each (Q07-4: "the prompts also need refinements").

## Files

| Action | Path |
|---|---|
| Modify | `prompts/<id>_<name>.txt` of the steps in T-06.1 |
| Create | `prompts/profiles/<profile>/<step>.txt` where only one profile differs (a file named by `prompt_replace` or `prompt_append`) |
| Modify | `docs/rules/schemas-and-prompts.md` (what the prompt of each step says and why) |

## Specification

For **each** prompt, in this order:

1. Run the fixed set on the current prompt with the models of the profile; keep the output (`before`).
2. Change **one** thing (the instruction that T-06.1 names as wrong).
3. Run the same set again (`after`); keep it.
4. Write in *Notes* what changed, the messages whose answer changed and whether the expected points are met better, the same or worse. Worse: revert.
5. The golden file changes: read the diff first and regenerate on purpose (`UPDATE_GOLDEN=1`).

A prompt that differs for one profile is a profile override (T-05.14), not a change of the generic prompt.

## Acceptance criteria

Each refined prompt has a `before` and an `after` run and a note; none breaks its schema (`test_schema_tree.py`, `assemble()`); the maintainer read each changed prompt.

## Verification

The baseline of the [tasks README](../README.md) section 3. Real runs cost money: ask before each.

### Change 5: `1_triage_specialist.txt`, a request the robot cannot do is `communication` (2026-11-05)

- **Why:** the finding of change 4. The triage prompt says a request the robot cannot do should be answered with a short refusal, but the domain section never said which domain it is: the model read the topic ("a file", "a computer", "pick up the cup") and chose `system`, `operations` or `movement`. A client that chains `identification` then `chat` would send such a request to `special` (6 calls) or `movement`. `default` does not route on the domain, so its calls did not change (51 before and after).
- **Change** (+196 characters, the only change of this prompt that makes it longer; the saving is in the calls of a chained client, not in tokens): (1) in the `communication` bullet: "A request for something the robot cannot do (see the robot capabilities above) is "communication" too: the robot just has to say briefly that it cannot." (2) The example of the CAPABILITY CHECK now names the domain: `domain "communication" (not "system")`. Done in two steps under one change: the first alone did not move the stable failure (below), so the example was added before committing, and the measurement repeated.
- **Measured** (real, `identification`, `proven`, the classification of each request, 3 runs each; reports `tests/output/profile_run_identification_2026-11-05_{imp_before_*,imp_after_*,imp_after_b*,unseen_old_*,unseen_new_*,after5*}.md`):
