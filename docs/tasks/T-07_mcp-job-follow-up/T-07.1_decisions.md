## Resolution

Answered by the maintainer in [Q10](../../setup/questionnaires/Q10_mcp-job-follow-up.md) on 2026-11-11:

1. **Code in the adapter**, no longer a rule of the operator prompt (Q10-4: default).
2. **`job_protocol` per server file**, `none` by default; only `dynamics_microservice` counts today and a new server starts as `none` (Q10-1: default).
3. **Waits:** the 60 s of the message as they are; 1 s between the first reads, doubling, never more than 5 s, measured in T-07.9 (Q10-5: default).
4. **Budget spent:** cancel the job and say it is still running (Q10-6: default).
5. **Unknown shape:** that action fails with a reason, its dependants are skipped, the writer says the query could not be completed, one log line with the server name (Q10-8: default).
6. **`custom` protocol:** not now (Q10-10: default).
7. **Shipment tools:** **offered in this epic** (Q10-11: B), as the new task [T-07.10](T-07.10_shipment-tools.md).

Also decided:

- **Two jobs in one answer: all or nothing** (Q10-9: B, not the default). Every job of the answer is followed; if one does not end in time, the ones still running are cancelled, **no table is given** (a table that did end is discarded), and the reply says the query is still running.
- The shape of 2026-11-11 stays unconfirmed until T-07.2 is answered; both shapes are supported (Q10-2: default). The request to the Go service is sent as written (Q10-3: default).
- No spoken "one moment" while it waits (Q10-7: default).
- **Roll-out:** the agent first, the server after (Q10-12: default); the maintainer is changing `dynamics_microservice` in another session, so T-07.2 can be answered from there.
- **Branch:** a new `feature_mcp_job_follow_up` from `feature` (Q10-13: default); not created yet (nothing is committed or branched unless asked). **T-07.9** is asked before it runs (Q10-14: default).

ADR-018 is Accepted (2026-11-11), with the two changes above.
