## Goal

Add the seam and change nothing in behaviour: a server file may declare a `job_protocol`, the default is `none`, and `none` does nothing.

## Files

| Action | Path |
|---|---|
| Create | `infrastructure/outbound/mcp/job_protocol.py` (the interface: `detect`, `poll`, `is_done`, `cancel`; the `JobRef` value: id and optional offset; the registry of names; `NoJobs` for `none`) |
| Modify | `infrastructure/outbound/mcp/config.py` (read `job_protocol` and, for later, `job_read_tool` and `job_cancel_tool` of a server file; an unknown name skips that server with a warning, as an unknown `type` does) |
| Modify | `infrastructure/outbound/mcp/tool_executor.py` (ask the protocol of the server after a call; with `none` return the answer as it is) |
| Create | `tests/test_mcp_job_protocol.py` |

## Specification

As in [ADR-018](../../decisions/ADR-018-mcp-job-follow-up-per-server.md) decisions 2 to 4. `detect(answer)` returns a `JobRef` or nothing; it never raises. The read tool is the one named by the server file and must be in its `allowed_tools`. A server file with no `job_protocol` behaves as today.

## Acceptance criteria

The registry rejects an unknown name; a server file without the field loads as `none`; with `none` the executor returns exactly what the server answered; the golden file does not change.

The baseline of the [tasks README](../README.md) section 3, and `python scripts/check_agent.py`.
