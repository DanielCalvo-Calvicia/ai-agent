## Goal

Prove the follow-up against the real `dynamics_microservice`, and measure the wait between two reads. **Ask the maintainer first: it calls the real service and, with `run_profile.py`, real models, and costs money.**

## What to do

1. `python scripts/check_agent.py` and `python -m pytest tests` pass.
2. Run the `dynamics` profile (`python scripts/run_profile.py dynamics`, or `--mock` first) with a message that makes the service answer with a job: the open orders of a test customer (`CL-1001` gave a job on 2026-11-11).
3. Check in the logs (never the values): the call, the number of reads, the outcome `job_done`; the reply has the data the user asked for in the user's language.
4. Check a message whose job cannot end in time, if the service allows to provoke one: the budget ends, `cancel_job` is called, the reply says it is still running.
5. Make one shipment call too (`shipment_tracking` for a test customer): the answer must reach the writer whole (T-07.11 calls it again if it is a job). Check that no message waited past the per-call limit (a call can take 25 s per slow step, 50 s with two chained: the T-07.2 open point).
6. Write in *Notes*: the shape that came, the number of reads, the time of each, the total, the tokens, and the value chosen for the wait between reads.

## Acceptance criteria

A real job is followed to its result with no model involved in the follow-up; the wait is set from the measure; every finding that is not fixed has its own task or a line in the epic's open points.

## Verification

The logs of the run (names, outcomes, durations only) and the printed reply.
