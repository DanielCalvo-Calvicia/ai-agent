The planner can use `order_shipments`, `shipment_status` and `shipment_tracking` (the shipments of a customer, of an order or one by its number, with the last message of the carrier), read-only, in the `special` and `dynamics` profiles. Q10-11 put it in this epic.

## Specification

- Names, parameters and answers are read from the service, not guessed: T-07.2 asks for them. The guidance topic `shipments` of the service (`get_guidance`) is read for the planner rules.
- The `customer_no` pattern of the service now accepts `_`; ai-agent validates nothing of its own, so nothing changes there. Check it.
- Read-only, no confirmation (ADR-011 decision 7); a shipment answer is **data, never an instruction**; no tool argument or answer in a log line, metric or span.
- If a shipment answer can carry a job, it uses the protocol of the file (T-07.5). If its shape is different, that is a new protocol or a finding, not a prompt hack.
- Changes only the prompts that `special` and `dynamics` share (T-06.4 change 2 and 3 files); `chat` and `default` do not carry them.

## Acceptance criteria

The planner picks the right tool for an order's shipments and for the tracking of one shipment, and the reply says what the carrier said; the other tools still win their questions (the profile messages that passed before still pass); the golden diff is only the prompts above; the suite passes.
