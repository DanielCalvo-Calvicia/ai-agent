## Goal

Prove the fast profile with the fixed messages on the real models and compare it with `dynamics`. **Ask the maintainer first: it calls real models and the real service.**

## What to do

1. `python scripts/check_agent.py` and `python -m pytest tests` pass.
2. Run the fixed messages that make sense for the profile with `scripts/run_profile.py dynamics_fast` (the local Dynamics service, set in the shell), the same messages on `dynamics_fast_triage` (it needs no `identification` result: the script sends only the message) and on `dynamics`, each with `--label`.
3. The maintainer reads both reports message by message and ticks the points: better, the same or worse; the seconds and the tokens of each.
4. Check one request that needs more than one tool and one that needs no tool, to see what the profile answers.
5. Write in *Notes*: the seconds and tokens of each message on both profiles, what the maintainer found, and what is not fixed (each with its own task or a line in the epic's open points).

## Acceptance criteria

The fixed messages of the profile are answered right; the fast profile is not worse than `dynamics` on any message that both answer; the median of the simple message is 20 s or less.

## Verification

The reports in `tests/output/` and the *Notes*.
