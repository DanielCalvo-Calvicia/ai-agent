## Goal

Every change of this epic is judged in seconds, but the log of an LLM call has no duration today (only tokens and cost). Add it first, so the "before" is measured and not estimated.

## Files

| Action | Path |
|---|---|
| Modify | `application/runtime/step/runner.py` (`send` measures the wall time of the call of one step, its waits and its fallback model included, with a monotonic clock) |
| Modify | `application/support/metrics.py` (the record of an LLM call gets `duration_ms`; the INFO line `LLM call` carries it; `SessionMetrics` sums it by step) |
| Modify | `infrastructure/outbound/usage/langfuse.py` (the metadata of a call carries `duration_ms`, only if the span does not already hold the times) |
| Modify | `scripts/run_profile.py` (the report of a message lists its steps with the seconds each took, and the total) |
| Modify | `tests/` (a test of the record and of the log line; a test of the report) |

## Specification

- `duration_ms` is a whole number of milliseconds, 0 or more. It measures the call of the step as the runner sees it (not the time to build the prompt before it).
- No other field of the log line changes; no argument, answer or prompt text is added.
- A step that fails still has its duration recorded.

## Acceptance criteria

The `LLM call` log line and the metrics record of a call have `duration_ms`; the report of `run_profile.py` shows seconds per step; the golden file does not change.
