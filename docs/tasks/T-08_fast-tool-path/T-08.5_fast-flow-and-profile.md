## Specification

- **Selector:** writes ONE `mcp_tool_call` action with a complete `mcp_context`, or `required_inputs` for a missing value (the run pauses and resumes as the special flow does), or ONE `generation` action when no tool fits (decision 4 of T-08.1 says what the reply says when the request needs more). It is shown only the read-only tools of its scope.
- **Caller:** calls the tool of the action through the helper; the result goes to `action.output` untouched, an error to `action.error`; a pending confirmation does not exist here (read-only only).
- **Writer:** one call that does what the draft writer and the editor do: the reply in the language of `message`, plain text, short and speakable, one honest sentence per error; the tool-answer rules come from the profile's append.
- **The token:** generate a random token with the command in `profiles/README.md`, write **only its SHA-256** in the profile, and give the token to the maintainer once, in chat. It is not written in any file.
- Nothing in the module or in the generic prompts names a server or a tool.

## Acceptance criteria

`scripts/check_agent.py` assembles the new profile and flow (data flow included); `--explain dynamics_fast` lists its steps, models, tools, prompts and hash; the three steps run with a scripted LLM (T-08.6); the module has no server name.
