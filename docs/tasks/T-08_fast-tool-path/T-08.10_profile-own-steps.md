## Goal

A profile can list its own `steps` and run them, with no flow file (Q11-7: B). Today `assemble()` accepts a profile's `steps` but `ProfileRunner._flow_of` refuses it (`profile 'x' lists its own steps: that needs steps as files (T-05.16)`), and `profiles/README.md` says so. The maintainer believed it was already done.

## Specification

- **Same behaviour as a flow file.** A profile whose `steps` equal the steps of a flow file runs identically: same calls, same pause and resume, same result. The flow name in the answer and in the metrics is the profile's name.
- The profile keys that go with `steps`: `result_from`, `on_pause`, `on_resume`, `tools` (as in a flow file); `flows.<profile name>` may override a step's models as for any flow. Exactly one of `flow` and `steps` stays required.
- `profile_hash` covers the steps (a change of the steps changes the hash).
- `scripts/check_agent.py --explain <profile>` lists the steps of such a profile.
- No shipped profile changes in this task: the first user is T-08.11.

## Acceptance criteria

A test profile with `steps` gives the same calls and the same result as the flow file with the same steps (a test builds both); a profile with `steps` that can pause pauses and resumes; a bad step name, a bad `on_pause` hook or a missing `result_from` is a problem of the profile, not an exception at run time; the golden file does not change.
