## Goal

The fast path has no gate step, so it must only be able to run tools that do not change anything. Carry the MCP `readOnlyHint` into `ToolDefinition` and refuse any other tool in the fast path.

## Files

| Action | Path |
|---|---|
| Modify | `domain/value_objects/llm_request/tool.py` (`read_only: bool = False`) |
| Modify | `infrastructure/outbound/mcp/tool_catalog.py` (reads `annotations.readOnlyHint` of each MCP tool; a tool without the hint is not read-only) |
| Modify | `application/support/tools/direct_call.py` (T-08.3: an optional check that refuses a tool whose definition is not read-only) and `application/support/tools/mcp_servers.py` (`read_only_only`) |
| Modify | `infrastructure/outbound/mcp/availability.py` (the names of the tools that are not read-only in its INFO line) |
| Modify | `tests/` (the catalog reads the hint; a tool without it is refused by the check; the Dynamics tools of the snapshot are read-only) |

## Specification

- **The check is at run time, not at assembly.** `assemble()` works from files only (T-05.6) and a tool's annotation is on the live server, so ADR-019 decision 8 (which says `assemble()` checks it) is corrected by a dated note: the selector is shown only the read-only tools of its scope, and the caller refuses any other one with a plain error. A profile whose scope has no read-only tool answers that it cannot help.
- The existing steps and the existing profiles are not affected (only the fast path asks for the check).
- `AI_AGENT_CHECK_MCP_<NAME>` (log only) may also list, by name, the tools that are not read-only.

## Acceptance criteria

`ToolDefinition.read_only` is set from the hint; a tool without the hint is refused by the fast path; the Dynamics snapshot is read-only; nothing of `special` or `dynamics` changes.

## Notes

- **2026-11-11, done.** `ToolDefinition.read_only` (default `False`); `MCPToolCatalog` reads `annotations.readOnlyHint` (`_read_only`: only a `true` counts; no annotation is not read-only); `describe_servers(..., read_only_only=False)` and `server_names(..., read_only_only=False)` show only the read-only tools (a server with none is left out; the scope of the step still applies first); `direct_call.is_read_only` and `call_directly(call, mcp_tools, mcp_list=None, read_only_only=False)`: with the flag, a tool not marked read-only is refused with a plain error (`The tool '<name>' is not marked read-only by its server, so the fast path does not run it.`) and **no server is called**, and without `mcp_list` nothing can be proved read-only, so it is refused too. The existing callers (the executor of `special` and `dynamics`) do not pass the flag: nothing of theirs changes. The optional `AI_AGENT_CHECK_MCP_<NAME>` check adds `not_read_only` (the names) to its one INFO line. `tests/test_read_only_tools.py` (12 tests, one with a real FastMCP server with annotated tools). Verified: **1563 passed**, `check_agent.py` ok, `split_schemas.py` ok, golden untouched.
- **What the live service says** (a listing of the local Docker service, names and flags only): every tool is read-only (`customer_card`, `customer_orders`, `order_status`, the three shipment tools, `get_guidance`, `list_workflows`, `get_job_result`) **except `cancel_job`**, which is not (it stops a job and deletes its result). So the selector of the fast flow will not be shown `cancel_job`, which is right: only the job follow-up of the adapter (ADR-018) calls it. `special` and `dynamics` still show it to the planner, as before.
- **A limit, written down:** the MCP specification calls annotations *hints*, so the check is only as good as the server; ai-agent trusts the servers of its own `mcps/` files. A server that marks a writing tool as read-only defeats it.
- **The ADR text is corrected** (decision 8 already says the check is at run time; a dated note was added there when the tasks were written).
