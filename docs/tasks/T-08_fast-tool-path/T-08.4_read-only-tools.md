## Goal

The fast path has no gate step, so it must only be able to run tools that do not change anything. Carry the MCP `readOnlyHint` into `ToolDefinition` and refuse any other tool in the fast path.

## Files

| Action | Path |
|---|---|
| Modify | `domain/value_objects/llm_request/tool.py` (`read_only: bool = False`) |
| Modify | `infrastructure/outbound/mcp/tool_catalog.py` (reads `annotations.readOnlyHint` of each MCP tool; a tool without the hint is not read-only) |
| Modify | `application/support/tools/direct_call.py` (T-08.3: an optional check that refuses a tool whose definition is not read-only) |
| Modify | `tests/` (the catalog reads the hint; a tool without it is refused by the check; the Dynamics tools of the snapshot are read-only) |

## Specification

- **The check is at run time, not at assembly.** `assemble()` works from files only (T-05.6) and a tool's annotation is on the live server, so ADR-019 decision 8 (which says `assemble()` checks it) is corrected by a dated note: the selector is shown only the read-only tools of its scope, and the caller refuses any other one with a plain error. A profile whose scope has no read-only tool answers that it cannot help.
- The existing steps and the existing profiles are not affected (only the fast path asks for the check).
- `AI_AGENT_CHECK_MCP_<NAME>` (log only) may also list, by name, the tools that are not read-only.

## Acceptance criteria

`ToolDefinition.read_only` is set from the hint; a tool without the hint is refused by the fast path; the Dynamics snapshot is read-only; nothing of `special` or `dynamics` changes.
