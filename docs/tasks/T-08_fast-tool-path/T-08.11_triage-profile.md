## Goal

The fast profile for a client that sends only the message (a web chat, the portal): the same three steps as `dynamics_fast` with the triage in front, so it needs no `identification` call (Q11-3: C). Named `<server>_fast_triage`, so `dynamics_fast_triage`. It is also the first profile that lists its own steps.

## Specification

- The triage step writes `user_goal` and `task_category`, so the rest of the flow reads what it reads in `dynamics_fast` (the data-flow check of `assemble()` proves it).
- A request that needs a missing value pauses at the triage or at the selector and resumes as the special flow does.
- The token: a random token, shown to the maintainer once in chat; only its SHA-256 is written in the file.
- The tool rules and prompts are the ones of `dynamics_fast` (shared files, not copies).

## Acceptance criteria

`scripts/check_agent.py` assembles the profile; a request with only the message gets an answer through the triage, the selector, the caller and the writer (scripted LLM: 3 model calls and one code step); a missing value pauses and resumes; the golden diff is only the new profile block.
