## Goal

A tool call whose tool and parameters are already decided is made by code, not by a model that rewrites the answer. One helper does it, and the action executor of `special` and `dynamics` uses it for the independent actions (decision 7 of the ADR; the fast flow uses it in T-08.5).

## Specification

- **When the helper is used:** the action has no dependencies and no subactions, its `mcp_context` has a server, a tool and a `parameters` object, and the executor has a tools port. Otherwise the LLM operator runs exactly as today.
- **What it does:** calls `call_tool` inside `watch_tool_failures`, so each call is still recorded (`record_tool_call`); the answer text is the result, untouched; a tool error goes to `error`. The adapter already retries once after a transport error or `retry_later` and follows the jobs (ADR-018): no re-ask loop here.
- **The data engineer** runs only when the answer does not start with a `key: value` line of the contract (an envelope or noise); otherwise the answer is given as it is.
- The scope of the step is respected (a tool the scope does not allow is refused as before).
- The helper names no server and no tool.

## Acceptance criteria

An independent MCP action runs with no model call; a dependent one still runs with the LLM operator; a tool error reaches `error`; the scope refuses a tool outside it; a contract answer skips the data engineer and an odd one goes through it; the tests of T-07 stay green; the golden diff is only the removed `phase5` and `phase6` calls.
