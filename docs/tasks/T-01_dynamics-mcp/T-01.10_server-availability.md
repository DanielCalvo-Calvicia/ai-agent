## Goal

A Business Central server that is down never makes the planner plan a call that cannot run, and the maintainer can opt in to a reachability check per server. Decided in Q03-5 and Q03-10, Q04-2.

## Specification

- **Hidden when down (Q03-5 A).** A server whose listing fails or is empty is not shown to the planner for that message: it is left out of `describe_servers` and of the server names the project manager may choose (`server_names`). When the user asks for Business Central data and no server is available, the reply says honestly that it is not reachable now (the existing failure path: the planner has no tool, so it says it cannot do it; the wording comes from T-01.6).
- **Cache.** A successful listing is already cached for the life of the process; a failed listing is cached for 60 s, so a down server costs at most one 10 s wait per minute. A server that comes back is picked up after the 60 s.
- **The optional check (Q04-2, variable A).** `AI_AGENT_CHECK_MCP_<NAME>=1` for each server, where `<NAME>` is the server name in upper case (`AI_AGENT_CHECK_MCP_DYNAMICS_MICROSERVICE`). Unset or `0` means no check. When set, the check lists the tools of that server at start-up and each time `/available` is called, and **only logs** the result: a warning that names the server when it is not reachable. **`/available` does not change** (its contract is in the bundled wheel, and it must stay free of cost: with the variable set the call does a network listing, which is the choice of whoever sets it).
- Never log a URL, an argument or an answer.

## Acceptance criteria

A dead server is hidden from the planner and the reply is honest; a down server costs at most one 10 s wait per minute; with the variable set a warning is logged at start-up and on `/available`; without it nothing is checked; `/available` answers exactly as before.

## Notes

- **2026-10-27, built.** `tool_catalog.py`: `FAILED_LISTING_TTL_SECONDS = 60` (a failed listing raises `ListingRecentlyFailed` without a network call until it passes; a success is kept as before), an injectable `clock`, and `refresh_tools(server)` (forgets tools and failure, lists again; what the check uses). The catalog no longer logs `exc_info` for a failed listing: it logs `server_name` and `error_type` (class names, also inside exception groups), because the text and traceback of a connection error can hold the address. `mcp_servers.py`: `server_names(mcp_list, mcp_tools=None)` and `describe_servers` leave out a server with no tools **only when there is a tools port** (without one every server is kept, so the golden file and the port-less tests do not change). `availability.py`: `McpAvailabilityCheck` and `check_variable()`; only the value `1` turns a check on; it logs a warning naming the server (or an info line when it is reachable) and returns the unreachable names. `fastapi.py`: an optional `AvailabilityCheck` callable runs in a worker thread on every `/available`; a failing check is logged and never changes the answer. `main.py`: builds the check from `toolExecutor.catalog`, runs it once at start-up and hands it to the route. `.env.example` and the environment, monitoring, api and architecture documents are updated.
