## Specification

- `capabilities.txt`: remove "No external service is connected"; list read-only Business Central data through tools (orders of a customer, the state of an order, a customer card), and that it can only read them, never change them. Keep "never invent data".
- Triage CAPABILITY CHECK: Business Central data is **not** an impossible external service; keep the rule for email, calendar, files and the internet.
- Domain: no new value. A request for business data is `data` (or another non-`communication` value) so it goes to the special flow (F10). Add one sentence and an example to the `communication` / other-values text so "orders of customer X" is not classified as small talk.
- The text must not assume the client is the robot: ai-agent also serves other clients (a web chat later) and does not care which one (Q02-2). Say "the user" in the new lines; the robot-specific lines of the file stay as they are (the mixture of robot and generic client is refined later).
- The reply is in the language of the user (Q01-4), in plain text (Q02-11 A), and may show the data the user asked for (Q01-3 A).
- Do not name a tool, a host or a company in these prompts: the tool list comes from the server.
- Regenerate the golden file with `UPDATE_GOLDEN=1 python -m pytest tests/test_flow_golden.py` **after reading the diff**; it must contain only these prompt changes.

## Acceptance criteria

With a scripted LLM, a request for a customer's orders is routed to the special flow; the golden diff is limited to the prompts above; a request the robot still cannot do (email) is still refused honestly.

## Verification

The baseline of the [tasks README](../README.md) section 3. Whether a real model routes it correctly is proved only by T-01.9.
