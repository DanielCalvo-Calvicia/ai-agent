## Goal

A tool call is not cut while the server is still waiting for its query, and it is not retried when a retry cannot help. The Go service waits up to 20 s (F4) and the current limit is 10 s for the whole session (F7).

## Specification

- Two limits: listing tools stays short (10 s); executing a tool uses a configurable limit from `AI_AGENT_MCP_CALL_TIMEOUT_SECONDS`, default **30**, always larger than the Go `MCP_JOB_WAIT`. An invalid value (not a positive number) falls back to the default with a warning.
- The limit covers connect, initialize and the call, as today.
- A timeout gives the existing `{"error": ..., "is_error": True}` answer; the message must say it was a timeout, so the planner can tell it from a tool error.
- **Retries (Q03-4 A).** Retry **only** a transport error (the server could not be reached or the connection broke) and `error (retry_later)`, **once**. **Never** retry a timeout, `error (input)`, `error (not_found)`, `error (source_problem)` or `error (internal)`. The rule is for MCP tool calls; the retries of an LLM call and of a step that answers `retry` stay as they are (`AI_AGENT_MAX_ATTEMPTS`).
- The total wait of a message that follows up a running query is 60 s (Q01-10); T-01.6 enforces it. This task only provides the call limit.

## Acceptance criteria

A transport error and `retry_later` are retried once and no other failure is retried; a server that answers after 15 s succeeds; one that never answers fails at the call limit with a timeout message; listing a dead server still gives up at 10 s.
