## Specification

- A local server over Streamable HTTP with the tools `customer_orders`, `get_job_result` and `list_workflows`, answering with the real shapes of F5: metadata lines plus a `|` table, `status: running` with a `job_id`, and `error (input): ...`.
- Scenarios through the router with a scripted LLM: orders of a customer (special flow, one MCP action, a spoken reply); a running answer then `get_job_result`; a tool error; a missing customer code (pause, then resume with the answer).
- The server's tools and instructions are placeholders: no real host, tenant or customer code.
- Confirm that `sse` and `streamable_http` servers can be configured together.
- **Snapshot (Q03-11 A):** a fixture holds the names and parameters of the tools taken from the Go documents; a test checks that the allowed list of `mcps/dynamics_microservice.json` is contained in it. The snapshot is refreshed by hand in T-01.9 from the real service.
- A tool result with an injected sentence must not change the plan or the reply (Q03-1).
- A request in Spanish gets a reply in Spanish, and one in English a reply in English (Q01-4); the reply is plain text (Q02-11).
- A table with many rows (more than 10) is reported without any limit added by ai-agent (Q02-12); a `hint` that the service capped the answer is passed on.
- The next request of the same session reaches the planner with the earlier user message and the reply that was sent; tool answers are not in the session (Q04-1, F12).
- No tool confirmation is asked (Q01-12).
- The cap of tool calls, the retry rule, a hidden dead server and the metrics each have a scenario (T-01.10, T-01.11, T-01.4, T-01.12).
- A test that captures the logs of a call and finds no tool argument and no tool answer in them (Q02-7).
- **The venv:** `windows` is missing. Create it with **Python 3.14** (`py -3.14 -m venv windows`), then `pip install -r requirements.txt` (it also installs `../shared-logging` in editable mode). **Ask once more right before installing** (Q04-7). The folder is git-ignored.
