## Goal

See the whole path work once against a real LLM and the real service. **The maintainer runs it** (Q01-14 A); the assistant prepares the command and says what to look at, and runs nothing itself. It costs money, and it reads Business Central data (read-only), with a test customer.

## Specification

1. Start `dynamics_microservice` with `MCP_EXPOSE_GENERIC_TOOLS=false` (T-01.1, decision 1); set `DYNAMICS_MCP_URL` (a public IP and port, only in the environment); set the models of the steps to the Claude Sonnet model of T-01.3, with the key of the enterprise account in `ANTHROPIC_API_KEY`; Langfuse is on with a trusted project (T-01.1, decision 2).
2. **The maintainer runs it** against the sandbox with a **test customer holding no real personal data** (the data policy of the enterprise account is `UNKNOWN`); the assistant prepares the command and says what to look at. Run `tests/manual/chat_session.py` or `full_flow_real_llm.py` with two requests: how many orders a customer has, and the state of one order.
3. Check: routing to the special flow, the tool and its inputs, the timeout, the speakable reply, the cost, what Langfuse stored, **the time of the whole message** (it fills the `UNKNOWN` caller timeout, Q03-6) and **refresh the snapshot of the tools** from the real service (Q03-11).
4. Record the result in `docs/requirements/requirements.md` (the "no real LLM call since the redesign" gap is only removed if this run covers the whole flow) and in the *Notes* of this task. Failures become new tasks.

**The maintainer decides when the epic is done**, after the run and a review of the Langfuse traces (Q03-13 A).

## Acceptance criteria

Both requests get a correct, short, speakable answer, or every failure is written down as a task.

## Verification
