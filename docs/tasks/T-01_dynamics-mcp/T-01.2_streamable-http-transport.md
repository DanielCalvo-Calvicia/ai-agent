## Goal

The MCP client can talk to a server that speaks Streamable HTTP (F1), next to SSE. Nothing else changes: the executor, the catalog API and the port stay as they are.

## Files

| Action | Path |

| Modify | `infrastructure/outbound/mcp/config.py` (`SUPPORTED_TYPES` gets `streamable_http`; the docstring) |
| Modify | `infrastructure/outbound/mcp/client_manager.py` (`session_scope` chooses the client by type) |
| Modify | `infrastructure/outbound/mcp/tool_catalog.py` (the check that skips a type that is not `sse` uses `SUPPORTED_TYPES`; docstrings) |
| Tests | `tests/test_mcp_streamable_http_integration.py` (new), `tests/test_mcp_config.py` |

## Specification

- `type` values: `sse` (unchanged) and `streamable_http`. A server of any other type is still ignored with the existing warning.
- `MCPClientManager.session_scope`: for `sse` keep `sse_client(url, headers=...)`; for `streamable_http` use the Streamable HTTP client of the `mcp` package. **Check the exact function and what it yields in the installed `mcp==1.26.0` before writing**: the streamable client may yield a third element (a session-id getter) that `ClientSession` does not take. Both send `dict(inject_headers())` so the trace context reaches the server.
- Keep `url` read from `config["config"]["url"]`; an empty or missing url raises a clear `ValueError` naming the server (not the url value).
- One session per call stays (the Go service is stateless, F1).
- Do not add authentication headers.
- **Logging (Q02-7):** a failed or slow MCP call logs only the tool name, the outcome and the duration. Never log the arguments or the answer (a customer code may be in them).

## Acceptance criteria

A FastMCP server over Streamable HTTP (stateless, JSON responses) on a free local port is listed and called through `MCPToolExecutor`; a tool error comes back as `is_error`; an `sse` server still works with the existing test; an unsupported type is ignored with a warning; no log line holds an argument or an answer.
