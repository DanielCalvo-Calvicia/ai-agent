## Goal

One record per LLM call with `profile`, `flow`, `step`, `model`, `client`, tokens and cost, and the hash of the assembled profile in the log and in Langfuse (PR-005 section 10, Q06-26 B, Q07-27, S6).

## Files

| Action | Path |
|---|---|
| Modify | `application/engine/support/metrics.py` (records keyed by `(profile, flow, step, model, client)`; totals by any key are computed from the records; a cost per message) |
| Modify | `infrastructure/usage/**` (Langfuse tags: profile, flow, step, client, hash) |
| Modify | `application/engine/assemble.py` (computes `profile_hash`: SHA-256 of the canonical JSON of the assembled profile, **without** the token hash) |
| Modify | `config/` (reserved: a step declares `data.reads`, a model catalog entry may declare `data_allowed`; nothing reads them; a test says so) |
| Modify | `docs/operations/monitoring.md`, `docs/security/security.md` |

## Specification

- The legacy phase id stays as a label next to the step name for continuity with `measured_runs.json` (Q07-9).
- No record holds a token, an `inputs` value, a tool argument or a tool answer.
- The data policy is **not built** (Q07-16): the fields are reserved so a later policy has one place to apply.

## Acceptance criteria

A run on mocks shows every key in the metrics; the hash changes when a model of the profile changes and does not when the token hash changes; a test proves that nothing enforces the reserved data fields.
