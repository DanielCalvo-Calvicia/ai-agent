## Goal

A profile may replace or append to the prompt of a step, from a file or inline (PR-005 sections 3.4 and 5, Q06-13, Q06-14, S5).

## Files

| Action | Path |
|---|---|
| Modify | `application/engine/phase_runner.py` (the only place a payload is built: applies `prompt_replace` or `prompt_append`) |
| Modify | `application/engine/assemble.py` (checks the overrides) |
| Create | `prompts/profiles/<profile>/<step>.txt` (none yet; the folder is documented) |
| Create | `tests/test_prompt_overrides.py` |

## Specification

- `prompt_append` adds text after the step's prompt; it cannot break the answer format. `prompt_replace` replaces the file and is allowed **only when the answer schema of the step is unchanged** (the format is in the schema, `docs/rules/schemas-and-prompts.md`); otherwise an assembly error.
- Both take `{"file": "..."}` or `{"text": "..."}`. The reply language follows the user (Q06-15): the generic prompts already say it and a profile does not change that.
- A prompt override is data from the repository; it is never built from `inputs`.

## Acceptance criteria

A profile with an appended prompt sends it (a test reads the payload); the golden file of every profile without an override is identical.
