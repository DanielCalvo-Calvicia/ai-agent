## Goal

Two commands and one table per profile (PR-005 sections 9 and 10, Q06-27, Q07-21 A).

## Files

| Action | Path |
|---|---|
| Modify | `scripts/check_agent.py` (`--explain <profile>`: the steps in order, the model and where it comes from, the tools, the prompts, the hash and the cost of a full plan) |
| Create | `scripts/run_profile.py` (`<profile>`: runs the fixed set of messages on the real models, saves the answers in `tests/output/`, writes `tested: <date>` in the profile; **asks before it runs**) |
| Modify | the generators of `docs/models/*` (one table per profile from the assembled profile, not from `PHASE_NAMES`) |
| Delete | `tests/manual/show_models.py` (replaced by `--explain`) |

## Specification

- The fixed set of messages is in `tests/manual/profile_messages.json`: a greeting, a question, a plan, a movement, a Dynamics question and a message in Spanish, each with what a good answer must contain (T-06.2 refines it). It costs a few cents per profile; the maintainer decides when to run it.
- The cost table of a profile uses the prices of `config/*_models.json`; the generated files are not edited by hand.

## Acceptance criteria

`check_agent.py --explain special` prints the assembled agent; the generators write one table per profile; `run_profile.py` on a mock adapter writes the answers and the note (the real run is T-05.11 and T-06.6).
