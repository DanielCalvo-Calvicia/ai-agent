## Goal

The tools a step may use are the intersection of what the profile, the flow and the step allow; a tool outside is neither shown to the model nor callable (PR-005 section 5, Q06-10 to Q06-12, S4).

## Files

| Action | Path |
|---|---|
| Modify | `application/engine/assemble.py` (resolves the tool set of every step of every profile) |
| Modify | `application/steps/special/project_manager.py` and `application/steps/special/mcp_operator.py` (`describe_servers` and the call take the step's tool set, not the whole list) |
| Modify | `infrastructure/outbound/mcp/tool_executor.py` (refuses a call outside the set) |
| Modify | `mcps/*.json` (the allowed-tools list stays the outer limit, Q03), `profiles/*.json` |
| Create | `tests/test_tool_scoping.py` |

## Specification

- A profile names a whole server (`"servers": ["dynamics_microservice"]`) or single tools as `server.tool`; a bare name that two servers share is an error at assembly. Nothing set at a level means no limit at that level.
- The planner receives only the allowed tools in `available_mcp_servers` (fewer tokens); the executor refuses any other (`AI_AGENT_MAX_MCP_CALLS_PER_MESSAGE` still applies).
- No log line, metric or span holds a tool argument or answer; the name, the outcome, the duration and the tries are the only fields (`CLAUDE.md`).
- `special` has every server, `dynamics` only the Dynamics one, `default` none (Q09-5).

## Acceptance criteria

A profile limited to one tool cannot see or call another (two tests); a flow or step that names a tool the profile does not allow gets nothing extra; the golden file does not change for the profiles whose tool list is unchanged.
