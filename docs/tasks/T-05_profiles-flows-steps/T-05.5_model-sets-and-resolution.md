## Goal

The ten tables of `config/step_models.json` become **model sets**; a profile names a set or an ordered list at any level; the most specific value wins; the ordered list is also the fallback (PR-005 section 5, Q07-10, Q07-11, Q06-23).

## Specification

- Resolution order for a step (most specific first, the whole list replaced): `overrides.<step>.models`, the flow entry, `profile.models`, the step's own default (the old `DEFAULT_MODEL`, now `default_models` of the step declaration). A set may be named at any level. An unknown set, an id not in the catalog or an empty list is an error that names the file.
- The first model of the list answers; when it is out of capacity (`capacity_problem`, ADR-014) the runner waits, then tries the next, once each. A daily quota still skips to the next at once. The Claude model sets keep a **one-item list** (no fallback): customer data must not move to another provider (ADR-014).
- The old profile `proven` is the model set of the profile `default` (the profile named in Q08-3).
- The ten model sets stay as they are, with their `_about` notes; the unverified ones are listed in T-05.7.

## Acceptance criteria

For every old profile name, the resolver gives, for every step, the same model id as `model_selection.choose()` gave on 2026-11-02 (a test builds the expected table from the old file in git history and compares); the golden file does not change; no environment variable selects a model any more.
