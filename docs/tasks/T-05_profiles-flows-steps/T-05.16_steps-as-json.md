## Goal

Every step is a JSON declaration; Python stays only for `code` steps and the named functions they use (PR-005 section 3.2, Q07-6 B, Q08-7, S7). **No behaviour change**: the golden file is byte-identical.

## Files

| Action | Path |
|---|---|
| Create | `step_defs/<name>.json` for the 12 LLM steps and the code steps (the example of PR-005 section 3.2) |
| Modify | `application/engine/phase_runner.py` (builds the payload from the declaration: prompt, answer pieces, `reads`, `writes`) |
| Create | `application/engine/declarative_step.py` (`reads` -> input dict, `writes` -> state fields, `for_each` for `llm_per_action`) |
| Delete | the constants and the `_build_input` and `_apply` of the Python step files that the declaration replaces; `application/steps/**` keeps only `code` steps and special inputs (the worker and the executor loop) |
| Modify | `application/engine/assemble.py` (checks `reads`/`writes` against the catalog of fields, the answer pieces against the schema tree) |
| Modify | `docs/rules/schemas-and-prompts.md` (a step declares its answer by combining existing schema pieces; a new piece needs a developer) |

## Specification

- A declaration may read and write **only fields of `config/state_fields.json`** (Q08-6): a non-coder cannot create a field. The answer schema is a combination of existing pieces of `schema/response/**`.
- Convert one step at a time and run the golden file after each; start with `draft_writer` (the example), end with the planner and the worker, whose inputs are the most special (history, answers, the tools). A step whose input is not a plain dict of fields keeps a **named Python function** that the declaration points to (Q08-7).
- The schema tree, the generated files and the Claude sanitizer are untouched.

## Acceptance criteria

The suite is green; the golden file is byte-identical after each conversion; `tests/test_plug_and_play.py` adds a step file and a prompt in a temporary folder and runs it; `git grep "PHASE_ID ="` finds only labels.
