## Goal

Everything the agent is made of (profiles, flows, step declarations, model sets, prompts) is read **once at start** through a port, so a source of the future (SQL, S3, LangChain services) changes nothing else (PR-005 section 8, Q07-17).

## Specification

- The data is plain: no Python inside a file; a hook, a condition or a code step is a **name** the code resolves (PR-005 sections 3.3, 8).
- Every file carries `schema_version` (an integer, `1` now); an unknown version is an error that names the file. No key starts with a letter that the format does not define, except keys that start with `_` (comments, as `step_models.json` does today).
- The snapshot is read once; nothing is re-read while the service runs (Q05-14). A different source is another adapter of the port, tested with a fake in the suite.
- A file that is not valid JSON names the file and the line.

## Acceptance criteria

Reading the five folders gives one snapshot; a fake source in the tests gives the same snapshot; `application/` does not import `infrastructure/`.

## Notes

- **2026-11-02:** built. `ConfigSourcePort` (`load_profiles`, `load_flows`, `load_step_defs`, `load_model_sets`, `load_prompt`), `Loaded` (`items` and `errors`) and `ConfigError` in `application/ports/outbound/config_ports.py`; `FileConfigSource` in `infrastructure/outbound/config/file_source.py`; `ConfigSnapshot` and `build_snapshot` in `application/engine/config_snapshot.py`; `composition_root/main.py` builds it at start and logs the counts and the files it could not use.
- **Deviation from the specification, on purpose:** a file that cannot be read (invalid JSON, not an object, a wrong `schema_version`, a name that is not the file's) is **not** an exception at load: it goes into `snapshot.errors` (`"<kind>/<name>"` -> message) and the other files still load. This is what PR-005 section 9 needs (a wrong profile is disabled in production and the others serve, Q07-18 C); `snapshot.raise_on_errors()` is the strict mode for the tests and `check_agent.py` (T-05.6). The check of unknown keys is not here: it is in `assemble()` (T-05.6).
- A prompt is read lazily and once (`snapshot.prompt(name)`), because the names come from the step declarations that do not exist yet; T-05.6 reads every prompt a profile uses at start. A prompt name cannot leave the project (`..`, absolute paths).
- Folders and files that start with `_` are skipped (`profiles/_unverified/`).
- Verification: 23 new tests in `tests/test_config_source.py`, 1027 passed in all, `split_schemas.py` no drift, the golden file untouched, `composition_root/main.py` compiles. The service was not started (it needs the provider keys).
