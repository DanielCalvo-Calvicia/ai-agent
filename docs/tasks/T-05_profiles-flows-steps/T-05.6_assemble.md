## Goal

One function builds the whole agent from the snapshot and refuses what cannot work (PR-005 section 9). It runs at start, in `scripts/check_agent.py` and in a test.

## Specification

Errors, each with the file and the key in the message:

1. an unknown name (step, flow, model, model set, tool, condition, hook) or an unknown key;
2. a profile with both `flow` and `steps`, or neither;
3. a step that reads a field that no earlier step writes, no `inputs` gives and no initial value gives; every `reads` and `writes` must be in the catalog of fields;
4. a flow with no `result_from`; the final result of a profile has no `user_goal` with its input and output (PR-005 section 7), except a profile that ends in a code step with no `Response`;
5. a model that cannot do what its step needs: a custom answer schema is run through the rules of **every** model of the lists (Claude's three levels of nesting, `anthropic_schema.py`, ADR-013);
6. `token_sha256` missing in any profile but `default`;
7. a tool named `server.tool` that is not in the snapshot of tools of `mcps/` (Q07-19 C), or a bare name that two servers share.

A profile that fails is **disabled** in production (its clients get `INVALID_PROFILE`, T-05.9); `check_agent.py` and the tests stop on the first. The safety gate and every other step are optional: dropping one is never an error (Q05-12).

## Acceptance criteria

One test per error above (a small bad profile in a temporary folder, the message asserted); a good snapshot assembles; production mode starts with one bad profile and serves the others.
